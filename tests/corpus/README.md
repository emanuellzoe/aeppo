# Detection corpus

Inert samples that aeppo must, or must not, report. `tests/test_corpus.py` scans them and compares the results with `expected.json`. Each entry in `expected.json` records the expected findings and the reason.

- **Do not run or import anything in this directory.** The samples only exist to be read as text. Commands are harmless (`echo hi`), URLs use the reserved `.invalid` domain, and reverse-shell samples point at `192.0.2.1` (TEST-NET-1, reserved for documentation and never routed).
- `negative/` holds false positives found while dogfooding. Each must stay quiet.
- `known_miss/` documents limitations. If aeppo starts detecting one, move it out and update `expected.json`.
- Secrets and bidirectional control characters are generated by the test instead of being stored here, so the repository holds no credential-shaped strings or hidden characters.

When you add a rule or fix a false positive, add a sample here with its expectation and reason. The test fails if a file has no entry in `expected.json`.

The repository's `.aeppo.toml` excludes `tests/corpus/**`, so `aeppo scan .` at the root stays clean.
